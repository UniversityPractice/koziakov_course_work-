## Что делает приложение

Салон закупает растения у поставщиков, хранит их на складе, собирает из них букеты и продаёт
букеты и отдельные растения клиентам, с доставкой курьером или самовывозом. Приложение позволяет
сотруднику вести весь этот учёт в браузере:

- **Справочники** — категории растений (с коэффициентом наценки), поставщики (со сроком поставки),
  растения и складские остатки, сотрудники (флористы и курьеры), клиенты. Для каждого — ввод,
  редактирование, удаление и просмотр. Растения, остаток которых ниже минимального, подсвечиваются.
- **Книга рецептов** — у каждого флориста свои шаблоны букетов с составом.
- **Заказы** — оформление заказа с букетами (по шаблону с возможностью изменить состав или
  индивидуальными) и отдельными растениями; для букета показывается рекомендуемая розничная цена.
  Заказ сохраняется одной транзакцией: если какого-то растения не хватает на складе, не сохраняется
  ничего. Растения списываются со склада сразу при оформлении — собранный букет уже не продать
  другому клиенту.
- **Статус заказа** — «принят» → «в доставке» → «вручён» (самовывоз: «принят» → «вручён»).
  Если курьер не застал получателя — «не вручён», заказ можно отправить снова. При отметке
  «вручён» база записывает время вручения, после этого заказ изменить нельзя. Отменить можно
  только заказ в статусе «принят»: он удаляется, растения возвращаются на склад.
- **Списания** — увядшие, бракованные и повреждённые растения с указанием причины.
- **Заявки на закупку** — база сама формирует заявки поставщикам, когда остаток опускается ниже
  точки заказа (с учётом расхода и срока поставки); сотрудник отмечает получение товара — склад
  пополняется.
- **Отчёты** — семь запросов задания:
  1. ТОП-10 растений в букетах за последний квартал;
  2. себестоимость и наценка каждого проданного букета;
  3. выручка и число заказов по флористам за период;
  4. растения ниже критического остатка с основным поставщиком;
  5. сезонность — заказы по месяцам предыдущего года;
  6. прайс-лист в формате XML по категориям (со скачиванием файла);
  7. среднее время сборки букета по сложности.

## Как это устроено

Основная бизнес-логика живёт **в базе данных**, приложение её только вызывает:

| Объект БД | Что делает |
| --- | --- |
| последовательности `посл_*` | выдают первичные ключи; приложение не передаёт `id`, а получает его через `RETURNING id` |
| функция `рекоменд_цена(букет_id)` | рекомендуемая цена = Σ количество × текущая закупочная цена × коэф. наценки категории |
| триггер `тр_склад` | при продаже и списании проверяет и уменьшает остаток, при отмене — возвращает; подставляет цены |
| `проверить_запас`, `сформировать_заявки()` | формируют заявки на закупку по точке заказа |
| триггер `тр_поставка` | пополняет склад при выполнении заявки |
| триггер `тр_статус_заказа` | проверяет переходы статусов заказа, ставит время вручения, запрещает менять вручённый и отменять переданный заказ |

Принципы реализации:

- **только нативный SQL**, без ORM — запросы пишутся вручную и выполняются драйвером `psycopg2`;
- все запросы **параметризованы**, все SQL-тексты собраны в одном модуле `app/sql.py`;
- одно соединение на сайт, запись — в транзакциях, ошибки БД показываются понятным текстом;
- база — 13 таблиц в нормальной форме Бойса–Кодда, имена таблиц и полей на русском.

## Стек

- Python 3.10+
- Flask — локальный сайт (HTML-шаблоны Jinja, без JavaScript-фреймворков)
- psycopg2 — драйвер PostgreSQL
- PostgreSQL 16

## Структура

```
database/          SQL-скрипты: схема, тестовые данные, 7 запросов, обновление базы, (необязательно) pg_cron
app/
  main.py          сайт: страницы заказов, справочников, заявок и отчётов
  orders.py        оформление заказа: черновик из формы, пересчёт цен, проверки, сохранение
  directories.py   настройки шести справочников и разбор полей формы
  config.ini       параметры подключения к БД
  db.py            подключение, выполнение запросов, транзакции, сообщения об ошибках
  sql.py           все SQL-тексты приложения
  templates/       HTML-шаблоны страниц
  static/          стили
  requirements.txt зависимости
  Dockerfile       образ сайта для docker compose
docker-compose.yml база и сайт
tests/             тесты (pytest): база, db.py, справочники, заказы, страницы сайта
```

## Запуск через Docker Compose

Нужен только Docker.

```
docker compose up -d --build
```

Затем открыть в браузере **http://localhost:8000**.

Поднимается PostgreSQL 16 (при первом запуске сама создаётся схема и загружаются тестовые
и дополнительные данные, а также 14 текущих заказов «в работе» — принятые, в доставке
и не вручённые, со временем от момента запуска), затем сайт. База работает по московскому времени. Сайт ждёт, пока база станет доступна, и подключается
к ней по внутренней сети compose (параметры из `app/config.ini` переопределяются переменными
`DB_HOST=db`, `DB_PORT=5432`). Сайт доступен только с этого компьютера.

- Только база (сайт на хосте): `docker compose up -d db`, затем `python app/main.py`.
- Другой порт сайта: `$env:APP_PORT=8080; docker compose up -d`.
- Остановить: `docker compose down`; с удалением данных: `docker compose down -v`.
- База создана до появления статусов заказа (на странице «Заказы» ошибка про столбец `статус`)?
  Обновить её без потери данных:
  `docker cp database florist-db:/` и
  `docker exec florist-db psql -U postgres -d florist -f /database/обновление_статус_заказа.sql`.
  Или пересоздать с нуля: `docker compose down -v`, затем `docker compose up -d --build`.
- Добавить в существующую базу свежие текущие заказы (повторный запуск добавляет ещё 14):
  `docker cp database florist-db:/` и
  `docker exec florist-db psql -U postgres -d florist -f /database/текущие_заказы.sql`.

## Установка и запуск без Docker Compose

1. Поднять PostgreSQL 16 (например, в Docker) и создать базу:

   ```
   docker run --name flowers-pg -e POSTGRES_PASSWORD=flowers -p 5433:5432 -d postgres:16
   docker exec -it flowers-pg createdb -U postgres -E UTF8 florist
   ```

2. Создать схему и загрузить тестовые данные:

   ```
   docker cp database flowers-pg:/database
   docker exec flowers-pg psql -U postgres -d florist -f /database/флористический_центр.sql
   docker exec flowers-pg psql -U postgres -d florist -f /database/тестовые_данные.sql
   docker exec flowers-pg psql -U postgres -d florist -f /database/дополнительные_данные.sql
   ```

   Третий скрипт необязателен: он дописывает реалистичные данные (около сотни записей в таблицах).
   Проще всего всё это делает `docker compose up -d` — база создаётся и заполняется сама.

   (Скрипты копируются в контейнер, а не передаются через `<`: в PowerShell перенаправление `<`
   не работает, а конвейер портит кириллицу.)

   Расписание через `pg_cron` (`database/pg_cron.sql`) необязательно: если расширения нет,
   заявки формируются кнопкой «Сформировать заявки» на сайте.

3. Установить зависимости:

   ```
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r app/requirements.txt
   ```

4. Проверить параметры подключения в `app/config.ini`, запустить и открыть http://localhost:8000:

   ```
   python app/main.py
   ```
